# 06 — Content Plan

## Content principles

1. **Evidence over adjectives.** A screen, a quote, or a number beats "delightful."
2. **Outcome first.** Put the result in the first viewport; earn the process.
3. **Name the trade-off.** A decision without a cost is a preference.
4. **Own the constraint.** NDA, small sample, missing data — say it.
5. **Write for the scan.** Headers, captions, and summaries carry the story.
6. **Keep the voice human.** Short sentences. Concrete nouns. No jargon.
7. **No placeholders at launch.** Bracketed numbers are a blocker, not a draft.

### Designing for Engagement (lead case study)

**Working title:** One platform, four kinds of loyalty
**Subtitle:** How a configurable archetype system let one loyalty platform fit telecom, banking, retail, and travel — without building four products.
**Outcome:** **+42% engagement · +67% point utilisation · +31% campaign participation · 3.2× reward redemption**; 8 B2B clients in 6 months, 12+ industries served.

**Content inventory**

| Asset | Status | Notes |
|---|---|---|
| Platform context | Have | B2B loyalty platform; telecom, banking, retail, travel |
| Research scale | Have | 6 industries, 500+ user sessions, 25+ platforms benchmarked |
| Industry-driver matrix | Have | The four-industry comparison from the project |
| Archetype definitions | Have | Point Utilization, Progress Driven, Reward Driven, Balanced Hybrid |
| Annotated archetype screens | Have | Four homepages with design notes |
| Module/card inventory | Needed | Shared components, with names |
| Decision log | Needed | Confirmed by Monalisha |
| Outcome data | Have | +42% engagement, +67% utilisation, +31% participation, 3.2× redemption |
| Permission | Needed | Employer + client naming + metric shareability |

**Story angle:** The homepage is not the product. The product is a system that can become four different homepages without four builds. Senior judgment is in what stays shared.

**Decisions to document:**
1. Four archetypes vs one adaptive homepage vs per-client bespoke.
2. Balance-first vs journey-first vs promotion-first hero.
3. Shared module library vs archetype-specific components.
4. How far client customisation can go before the system stops being a system.

**Reflection:** What to test earlier; how to govern configurability.

**Source notes:** [11 — Project Source Notes](./11-project-source-notes.md#1-designing-for-engagement).

### Re-designing agent's dashboard

**Working title:** A queue, not a feature list
**Subtitle:** Rebuilding an agent dashboard around the call, not the record — and cutting the information that made the day harder.
**Outcome:** **75% independent task completion** in a 5-agent usability test; the redesigned board shipped. Not a speed claim.

**Content inventory**

| Asset | Status | Notes |
|---|---|---|
| Ops context | Needed | Agent day, call volume, handoffs |

| Usability test | Have | 5 agents, Namibia/Zambia, 75% independent completion |
| IA reorganisation | Have | Old → information shown → Stats / Call-related / General info |
| Design library | Have | Colour, type, components |
| Key screens | Have | Dashboard, incoming call, callbacks, performance |
| States | Needed | Empty queue, call, error, follow-up |
| Build/QA | Needed | What shipped differently |
| Post-launch data | Needed | Task time, errors, adoption |
| Permission | Needed | Jabu sign-off |

**Story angle:** Complexity is not solved by fewer features; it is solved by a better hierarchy, clearer states, and a system that holds.

**Decisions to document:**

2. Fixed customer context vs collapsible context.
3. One dense board vs tabs plus a performance view.
4. Filtering model and call-result logic tree.

**Reflection:** What to measure earlier; what to change in the system.

### If metrics are unavailable

Use the highest honest rung:

- Directional: "roughly a third faster," "about 2× more."

Never invent a number. Never imply a causal claim you cannot defend.

## Copy deck structure

Create a single source of truth (Notion or a markdown file) with:

1. **Global:** name, role, location, email, LinkedIn, availability, résumé URL.
2. **Home:** eyebrow, H1, subhead, CTAs, proof strip, work rows, approach, teasers, contact.
3. **Case studies:** one file per project, following the template.
4. **Systems:** one file.
5. **About:** one file.
6. **Notes:** one file per essay.
7. **Meta:** title, description, OG copy for each page.
8. **Microcopy:** buttons, menu, 404, form states, toast, captions.

### Microcopy rules

- Buttons: verb + object. "See the work," "Download résumé," "Read the case study."
- Links: descriptive. No "click here."
- Errors: plain language, next step.
- Empty states: explain the state, offer an action.
- 404: "This page doesn't exist. Here's the work."

## Testimonials

### Selection criteria

- One about judgment or impact.
- One about collaboration.
- One about craft or speed, with context.
- Named, titled, verifiable.
- Permission to publish.

### Suggested structure

> "[Specific observation about how she thinks or works]."
> — Name, Title, Company · Relationship

### Avoid

- Generic praise ("great team player").
- Quotes about speed alone.
- Five quotes; three is enough.
- Stock headshots; use real photos or initials.
